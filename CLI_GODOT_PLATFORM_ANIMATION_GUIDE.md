# CLI-Only Godot Platform Animation Guide

This document records how this project was created and how to keep developing it without opening the Godot editor UI. It is intended as a reusable memory document for future CLI-first Godot projects.

## Environment

- Workspace root: `D:\workspace\AIgamedev`
- Project directory: `D:\workspace\AIgamedev\Godot_v4.6.2-stable_win64.exe\TestProject`
- Godot console binary: `D:\workspace\AIgamedev\Godot_v4.6.2-stable_win64.exe\Godot_v4.6.2-stable_win64_console.exe`
- Verified Godot version: `4.6.2.stable.official.71f334935`

The Godot documentation says a project can be created from the command line by making a directory and adding a `project.godot` file. Reference: https://docs.godotengine.org/en/latest/tutorials/editor/command_line_tutorial.html#creating-a-project

## Project Creation Steps

From PowerShell:

```powershell
Set-Location 'D:\workspace\AIgamedev\Godot_v4.6.2-stable_win64.exe'
New-Item -ItemType Directory -Force -Path '.\TestProject'
Set-Location '.\TestProject'
New-Item -ItemType File -Force -Path '.\project.godot'
```

In this project, the files were authored directly as text:

- `project.godot` defines the project name, viewport size, stretch mode, and main scene.
- `Main.tscn` defines a single `Node2D` root with `res://scripts/Main.gd` attached.
- `scripts/Main.gd` builds the platform test scene, generated castle background, floor collision, and HUD.
- `scripts/Player.gd` is the player class. It slices the processed 8x6 runtime sheet and maps frame ranges to key-driven animations.

No editor UI, plugins, or export templates are required.

```text
  tools/
    fit_background_16x9.py
    process_character_sheet.py
  CLI_GODOT_PLATFORM_ANIMATION_GUIDE.md
```

The source files to hand-author are `project.godot`, `Main.tscn`, scripts, raw source assets, generated runtime assets under `assets/`, tools, and this guide. The `.godot/` directory, `.uid` sidecars, and `.import` files are generated by Godot when CLI validation/import commands run.

The `raw/` folder is source-only and contains `.gdignore` so Godot does not import source art directly. Runtime assets should be generated or copied into an organized folder such as `assets/characters/`, `assets/backgrounds/`, `assets/sfx/`, or `assets/ui/` before being referenced from scenes or scripts.

## Asset Notes

`raw/Character.png` is the source animation sheet. `assets/characters/Character_processed.png` is the only character sheet referenced by the game.

The raw sheet layout is 8 columns by 8 rows. The current prototype uses source frames for idle, movement-like poses, jump-like poses, block, and attack. Other raw poses are kept only in `raw/Character.png` until the game needs more actions.

- Frames `0-7`: idle
- Frames `8-23`: attack
- Frames `24-31`: block

The file on disk currently measures `1254x1254`, not `1024x1024`. Run `tools/process_character_sheet.py` to produce `assets/characters/Character_processed.png`, which normalizes the runtime sheet into `128x128` cells. The processor preserves the original RGB data for the character/effects and creates a separate binary alpha silhouette mask: figure pixels are fully opaque, and outside-figure pixels are fully transparent.

The current runtime sheet is `1024x768`, arranged as 8 columns by 6 rows with 48 frames. The allocation follows common 2D action platformer timing: 8 frames for idle, 8 for each walk direction, 4 for jump, 8 for block, and 12 for attack.

- Frames `0-7`: idle
- Frames `8-15`: left walk
- Frames `16-23`: right walk
- Frames `24-27`: jump
- Frames `28-35`: block
- Frames `36-47`: attack

`assets/backgrounds/castle_lobby.png` was generated as a pixel-art ancient castle lobby background to match the fantasy sprite style. Run `tools/fit_background_16x9.py` to produce `assets/backgrounds/castle_lobby_16x9.png`, a `1280x720` stage image that keeps the full original background visible inside a 16:9 game window.

Asset preparation commands:

```powershell
python tools\process_character_sheet.py
python tools\fit_background_16x9.py
```

## Validation Commands

Set these variables in PowerShell to make the commands easier to reuse:

```powershell
$Godot = 'D:\workspace\AIgamedev\Godot_v4.6.2-stable_win64.exe\Godot_v4.6.2-stable_win64_console.exe'
$Project = 'D:\workspace\AIgamedev\Godot_v4.6.2-stable_win64.exe\TestProject'
```

Confirm the binary works in CLI mode:

```powershell
& $Godot --version
& $Godot --help
```

Check the game script for parser errors:

```powershell
& $Godot --headless --path $Project --check-only --script scripts/Main.gd
& $Godot --headless --path $Project --check-only --script scripts/Player.gd
```

Force Godot to import and validate the project without opening the editor UI:

```powershell
& $Godot --headless --path $Project --import
```

Run the project for a short headless smoke test:

```powershell
& $Godot --headless --path $Project --quit-after 5
```

## Manual Playtest

To play from the command line with a visible window:

```powershell
& $Godot --path $Project
```

Controls:

- Move left: `A` or left arrow
- Move right: `D` or right arrow
- Jump: `W`, `Space`, or up arrow
- Attack animation: `J`
- Block animation: hold `K`

## Game Implementation Notes

The sample is deliberately small and CLI-authored. `Main.gd` creates the background, player, floor collision, and HUD at runtime.

`Player.gd` extends `CharacterBody2D`, creates its `Sprite2D` and collision shape in code, applies gravity, and uses `move_and_slide()` for simple platform movement.

Animation uses `Sprite2D.region_rect` instead of editor-created `SpriteFrames`. This keeps the sprite sheet slicing explicit and reproducible from code.

## Future CLI Workflow

Use the same loop for future changes:

1. Edit `.gd`, `.tscn`, and `project.godot` files as text.
2. Keep source-only art under `raw/`, and generate or copy runtime assets into organized `assets/` folders before referencing them.
3. Run the script parser checks.
4. Run the headless import check.
5. Run the short headless smoke test.
6. Launch the visible game from the command line only when manual interaction is needed.

This keeps the project reproducible for future CLI-driven Godot experiments.
